End-to-End VDI Onboarding Pipeline

From three disconnected systems and 2 hours of daily Excel work to a single 10-minute reproducible run with anomaly detection — now operated by a teammate via SOP.

Python pandas BeautifulSoup PowerShell Active Directory SOP
~250 workers onboarded / month
2 h → <10 min daily processing time
1 year history in one tracker
SOP-driven operated by a teammate

Problem: Onboarding contractor VDI access required reconciling data across three systems — an ITSM ticket export (metadata buried in HTML cells), an identity-management warehouse, and a year-long historical tracker. The manual Excel reconciliation took up to two hours every day; missed AD group assignments re-opened as analyst tickets downstream.

Solution — a four-stage pipeline:

  1. Parse — a Python script extracts ~10 structured fields per worker from the ITSM export’s HTML cells (name, manager, region, access pool, start date, rehire flag, contact email).
  2. Reconcile — cross-references parsed records against the identity-management export to attach assigned usernames, with name normalisation handling casing, middle initials, and preferred-name variants.
  3. Anomaly detection — checks each (pool, region) combination against the rolling 12-month history. Combinations seen in the past 6 months auto-populate the correct security group; unseen combinations are flagged for manual review (most likely a new pool, or one that’s been retired).
  4. Provision & verify — PowerShell + ActiveDirectory module bulk-adds users to their security groups, then immediately re-reads membership to surface any mismatches before the batch closes.
View anomaly-detection logic (pool history lookup) 
def flag_new_pool_combinations(records, history, window_days=180):
    """For each record, check whether its (pool, region) combination
    has been used in the rolling history window.

      • Seen recently     -> auto-populate the historical security group.
      • Not seen recently -> flag for manual review (new or retired pool).
    """
    cutoff = datetime.now() - timedelta(days=window_days)
    history["seen_at"] = pd.to_datetime(history["seen_at"])
    recent = history[history["seen_at"] >= cutoff]

    # Lookup: (pool, region) -> most recent security group seen in window
    lookup = (
        recent.sort_values("seen_at", ascending=False)
              .drop_duplicates(subset=["pool_name", "region"])
              .set_index(["pool_name", "region"])["security_group"]
              .to_dict()
    )

    def resolve(row):
        return lookup.get((row["pool_name"], row["region"]))

    records["security_group"]      = records.apply(resolve, axis=1)
    records["needs_manual_review"] = records["security_group"].isna()
    return records

Outcomes

  • Daily processing reduced from ~2 hours to under 10 minutes, including AD remote-desktop launch and verification checks.
  • One year of onboarding history consolidated into a single searchable tracker.
  • Group-assignment errors caught at the source rather than as downstream re-opened tickets.
  • Now run by a teammate following the SOP — the automation belongs to the team, not just me.

ServiceNow Ticket Parser

Python pandas BeautifulSoup ServiceNow Active Directory View on GitHub ↗

Problem: ServiceNow ticket exports store ~10 fields per worker — legal name, manager, region, VDI pool, start date, rehire flag, contact email — inside a single HTML-formatted cell. Manual extraction across daily batches was slow and error-prone.

Solution: The parser stage of the onboarding pipeline. BeautifulSoup strips the HTML, a single regex table maps friendly field names to their patterns, and one normaliser handles preferred-name variants and middle initials so the parsed records join cleanly against the identity-management export downstream.

View source (snow_parser.py — Stage 1) 
FIELD_PATTERNS = {
    "first_name":    r"(legal[\s_-]?first[\s_-]?name|first[\s_-]?name)",
    "last_name":     r"(legal[\s_-]?last[\s_-]?name|last[\s_-]?name)",
    "manager":       r"(people[\s_-]?manager|manager[\s_-]?name|manager)",
    "region":        r"(geographic[\s_-]?region|region)",
    "pool_name":     r"(pool[\s_-]?name|vdi[\s_-]?profile)",
    "start_date":    r"(request[\s_-]?start[\s_-]?date|start[\s_-]?date)",
    "rehire":        r"(ever[\s_-]?worked|previous[\s_-]?employee|rehire)",
    "contact_email": r"(personal[\s_-]?email|contact[\s_-]?email)",
}


def parse_ticket_html(raw: str) -> dict:
    """Extract structured fields from one ticket's HTML metadata cell."""
    record = {k: None for k in FIELD_PATTERNS}
    if not raw or isinstance(raw, float):
        return record

    text = BeautifulSoup(str(raw), "html.parser").get_text(separator="\n")

    for line in text.splitlines():
        line = line.strip()
        if not line or ":" not in line:
            continue
        for field, pattern in FIELD_PATTERNS.items():
            if record[field] is None and re.search(pattern, line, re.I):
                m = re.search(r":\s*(.+)", line)
                if m:
                    record[field] = m.group(1).strip()
                break

    if record["first_name"] and record["last_name"]:
        record["full_name"] = f"{record['first_name']} {record['last_name']}"

    if isinstance(record["rehire"], str):
        record["rehire"] = record["rehire"].lower().startswith(("yes", "true", "y"))

    return record


def normalise_name(name: str) -> str:
    """'John A. Smith' and 'john   smith' both -> 'john smith'."""
    if not name:
        return ""
    name = re.sub(r"\s+\w\.\s+", " ", name)
    return re.sub(r"\s+", " ", name.strip().lower())


def attach_usernames(tickets, identity):
    """Join parsed tickets to the identity-management export on normalised name."""
    tickets["_key"] = tickets["full_name"].apply(normalise_name)
    identity["_key"] = identity["full_name"].apply(normalise_name)
    return tickets.merge(
        identity[["_key", "username"]], on="_key", how="left"
    ).drop(columns="_key")

AD Group Bulk Provisioning

PowerShell Active Directory Automation VDI Onboarding

Problem: During VDI onboarding, each new hire must be added to an AD security group that corresponds to their desktop pool. Processing batches of 10–30 users per week manually is repetitive, slow, and a source of provisioning errors if order is mismatched.

Solution: A PowerShell script that takes paired lists of users and groups, validates that the counts match before executing, and runs bulk Add-ADGroupMember calls with per-entry success and failure output. Used as a standard step in the weekly onboarding run.

View source 
Import-Module ActiveDirectory

# Paired lists — order must match: User 1 -> Group 1, User 2 -> Group 2
$users = @(
    "user1",
    "user2",
    "user3"
)

$groups = @(
    "SG-VDI-POOL-EMEA-01",
    "SG-VDI-POOL-EMEA-01",
    "SG-VDI-POOL-US-02"
)

if ($users.Count -ne $groups.Count) {
    Write-Host "ERROR: User count ($($users.Count)) does not match group count ($($groups.Count))." `
               -ForegroundColor Red
    exit
}

for ($i = 0; $i -lt $users.Count; $i++) {
    try {
        Add-ADGroupMember -Identity $groups[$i] -Members $users[$i]
        Write-Host "Added  '$($users[$i])'  ->  '$($groups[$i])'" -ForegroundColor Green
    } catch {
        Write-Host "FAILED '$($users[$i])'  ->  '$($groups[$i])': $_" -ForegroundColor Red
    }
}

Overview

This article documents the end-to-end process for provisioning VDI desktop pool access for new hires. It is intended for IT Support Specialists responsible for processing onboarding requests received via the ITSM queue. Follow steps in order; do not proceed to Step 3 until Step 2 is fully verified.

Prerequisites

  • Access to the ITSM platform (ticket queue and reports)
  • Access to the Identity Management Portal
  • Active Directory administrative rights (AD Module for Windows PowerShell)
  • Read access to Omnissa Horizon Admin Console
  • Access to the Onboarding Portal (CSV upload)
  • Edit access to the shared onboarding tracker

Step 1 — Tracker Update

  1. Export new-hire tickets from the ITSM report. The report is pre-filtered to show only tickets not yet marked as processed, preventing duplicate entries.
  2. Paste the exported ticket content into the ITSM Import tab of the onboarding rough tracker.
  3. Open the Identity Management Portal and navigate to the New Hire Password tab. Set the date picker to start date + 1 day, then paste the user list into the Identity Sheet in the rough tracker.
  4. Copy the contents of the Print New sheet and paste as Values Only into the actual tracker to preserve formatting.
  5. Return to the ITSM report and append – added to tracker to each processed ticket's short description. This prevents the ticket from reappearing on subsequent exports.

Note: The report filter relies on the absence of the suffix above. Always update ticket descriptions before closing the ITSM tab.

Step 2 — AD Pool Provisioning

  1. For each user, look up the corresponding AD security group using the Group Lookup Tool. If the group is not found (this occurs when the value is a pool name rather than a group name), search the correct pool in the Omnissa Horizon Admin Console by region.
  2. Use the provisioning script template (see AD Group Bulk Provisioning above) to populate the user and group arrays. Verify order carefully — User 1 must map to Group 1.
  3. Paste the completed script into Active Directory Module for Windows PowerShell and execute. Review the per-line output before proceeding; any red failure lines must be resolved before Step 3.

Troubleshooting: "Object not found" on a user — verify spelling against the Identity Portal. "Group not found" — re-confirm the pool in Horizon Admin Console and check the region.

Step 3 — Onboarding Portal Upload

  1. Rehires first — check the Identity Management Portal for returning employees and process them before new hires.
  2. Only upload users who have been successfully added to an AD group. If a pool name is missing from the tracker, confirm with the user's manager or account team before uploading.
  3. Copy columns H through K from the tracker and paste into sample.csv, keeping headers intact.
  4. Upload the CSV to the Onboarding Portal with the VDI Hire checkbox selected.
  5. Verify that the Collected LDAP status is green for every user before closing the portal.
  6. Enter the upload date in the Upload Date column of the tracker to mark the batch as complete.

Verification Checklist

  • All ITSM tickets appended with – added to tracker
  • Tracker fully populated — no blank pool names
  • PowerShell output shows no failures
  • Onboarding Portal shows green LDAP status for all users
  • Tracker upload date column updated for the batch

Part 1 — Meeting Room AV Troubleshooting

Covers Logitech Rally Bar setups connected via MS Teams Rooms in the Dublin office.

Common Issues & Resolutions

  1. Camera not detected in Teams — unplug and replug USB-C hub, wait 15 s for device re-enumeration. If it persists, restart the Teams Rooms console from the admin panel.
  2. No audio / mic not picking up — verify the Rally Bar is set as the default audio device in Windows Sound settings. Check mute state on the physical hub unit.
  3. Display shows “No signal” — confirm HDMI input selection on the room display. Test with a direct laptop connection to isolate whether the issue is the switcher or the cable.
  4. Teams Rooms console frozen / black screen — hold power on the compute unit for 10 s. For Logitech TAP-based rooms, reboot via the Logitech Sync portal to avoid a physical site visit.
  5. Firmware update loop — do not interrupt an active firmware cycle. If stuck, factory reset from the admin menu and re-pair to the room account via Logitech Sync.

Escalate if: hardware fault confirmed (physical damage, burnt smell) — log as hardware replacement in ServiceNow and attach photo evidence.

Part 2 — Laptop Imaging & Refresh

Pre-imaging Checklist

  1. Verify device is in the asset tracker — confirm serial number matches the ServiceNow CI record.
  2. Wipe existing data: boot to WinPE and run secure erase. For BitLocker-encrypted drives, confirm the recovery key has been escrowed before wiping.
  3. Check BIOS: Secure Boot enabled, TPM 2.0 active, boot order set to network first for PXE.

Imaging

  1. Boot to PXE or USB imaging stick and select the correct image for the device model and region (EMEA standard image).
  2. Let imaging complete without interruption — typical time: 20–40 min depending on drive speed.
  3. On first boot: join domain, apply GPO, confirm Windows Update resolves to current patch level.

Post-imaging Checklist

  • Asset tag confirmed in ServiceNow CI record
  • Device joined to domain and in correct OU
  • User account logs in successfully, MFA enrolled
  • Core apps present: Teams, Outlook, Chrome, VPN client
  • BitLocker enabled and recovery key escrowed
  • Ticket updated with imaging date and build version
