ServiceNow Ticket Parser

Python pandas BeautifulSoup ServiceNow Active Directory

Problem: ServiceNow ticket exports store all user information — full name, VDI pool assignment, login ID — in a single HTML-formatted column inside an Excel file. Extracting and reconciling this data manually when processing batches of new-hire tickets was slow and error-prone.

Solution: A Python CLI tool that reads the Excel export, parses the HTML with BeautifulSoup, and outputs a clean CSV with structured columns ready to cross-reference against Active Directory for pool provisioning. Accepts the input file, optional output path, and configurable column name as arguments.

View source (snow_parser.py) 
#!/usr/bin/env python3
"""
ServiceNow Ticket Parser
Extracts full name, VDI pool, and username from HTML-formatted
columns in ServiceNow Excel exports.

Usage:
    python snow_parser.py tickets.xlsx
    python snow_parser.py tickets.xlsx -o parsed.csv -c caller_info
"""

import sys, re, argparse
from pathlib import Path

import pandas as pd
from bs4 import BeautifulSoup


def parse_user_info(raw: str) -> dict:
    """Parse one HTML-formatted cell from a ServiceNow export column."""
    fields = {"full_name": None, "pool_name": None, "username": None}
    if not raw or isinstance(raw, float):
        return fields

    text = BeautifulSoup(str(raw), "html.parser").get_text(separator="\n")

    for line in text.splitlines():
        line = line.strip()
        if not line:
            continue
        if re.search(r"(full[\s_-]?name|display[\s_-]?name)", line, re.I):
            m = re.search(r":\s*(.+)", line)
            if m: fields["full_name"] = m.group(1).strip()
        elif re.search(r"(pool|desktop[\s_-]?pool|vdi[\s_-]?pool)", line, re.I):
            m = re.search(r":\s*(.+)", line)
            if m: fields["pool_name"] = m.group(1).strip()
        elif re.search(r"(user[\s_-]?name|login[\s_-]?id|sam)", line, re.I):
            m = re.search(r":\s*(\S+)", line)
            if m: fields["username"] = m.group(1).strip()

    return fields


def process_export(input_path, output_path=None, column="user_info"):
    src = Path(input_path)
    if not src.exists():
        sys.exit(f"File not found: {src}")

    df = pd.read_excel(src)
    if column not in df.columns:
        sys.exit(f"Column '{column}' not found.\nAvailable: {list(df.columns)}")

    parsed = df[column].apply(parse_user_info)
    df["full_name"] = [r["full_name"] for r in parsed]
    df["pool_name"] = [r["pool_name"] for r in parsed]
    df["username"]  = [r["username"]  for r in parsed]

    missing = df["full_name"].isna().sum()
    dest = Path(output_path) if output_path else src.with_name(f"{src.stem}_parsed.csv")
    df[["full_name", "pool_name", "username"]].to_csv(dest, index=False)

    print(f"Parsed {len(df) - missing}/{len(df)} rows  ->  {dest}")
    if missing:
        print(f"Warning: {missing} rows could not be parsed.")


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("input")
    ap.add_argument("-o", "--output")
    ap.add_argument("-c", "--column", default="user_info")
    args = ap.parse_args()
    process_export(args.input, args.output, args.column)

AD Group Bulk Provisioning

PowerShell Active Directory Automation VDI Onboarding

Problem: During VDI onboarding, each new hire must be added to an AD security group that corresponds to their desktop pool. Processing batches of 10–30 users per week manually is repetitive, slow, and a source of provisioning errors if order is mismatched.

Solution: A PowerShell script that takes paired lists of users and groups, validates that the counts match before executing, and runs bulk Add-ADGroupMember calls with per-entry success and failure output. Used as a standard step in the weekly onboarding run.

View source 
Import-Module ActiveDirectory

# Paired lists — order must match: User 1 -> Group 1, User 2 -> Group 2
$users = @(
    "user1",
    "user2",
    "user3"
)

$groups = @(
    "SG-VDI-POOL-EMEA-01",
    "SG-VDI-POOL-EMEA-01",
    "SG-VDI-POOL-US-02"
)

if ($users.Count -ne $groups.Count) {
    Write-Host "ERROR: User count ($($users.Count)) does not match group count ($($groups.Count))." `
               -ForegroundColor Red
    exit
}

for ($i = 0; $i -lt $users.Count; $i++) {
    try {
        Add-ADGroupMember -Identity $groups[$i] -Members $users[$i]
        Write-Host "Added  '$($users[$i])'  ->  '$($groups[$i])'" -ForegroundColor Green
    } catch {
        Write-Host "FAILED '$($users[$i])'  ->  '$($groups[$i])': $_" -ForegroundColor Red
    }
}

VDI Onboarding: End-to-End Provisioning Guide

Technical Writing VDI Active Directory Omnissa Horizon ServiceNow

Context: Internal knowledge base article written to standardise the VDI new-hire onboarding workflow across the IT Support team. Read article
Author: Olena Karpenko Last updated: April 2026 Category: VDI · Onboarding · Active Directory

Overview

This article documents the end-to-end process for provisioning VDI desktop pool access for new hires. It is intended for IT Support Specialists responsible for processing onboarding requests received via the ITSM queue. Follow steps in order; do not proceed to Step 3 until Step 2 is fully verified.

Prerequisites

  • Access to the ITSM platform (ticket queue and reports)
  • Access to the Identity Management Portal
  • Active Directory administrative rights (AD Module for Windows PowerShell)
  • Read access to Omnissa Horizon Admin Console
  • Access to the Onboarding Portal (CSV upload)
  • Edit access to the shared onboarding tracker

Step 1 — Tracker Update

  1. Export new-hire tickets from the ITSM report. The report is pre-filtered to show only tickets not yet marked as processed, preventing duplicate entries.
  2. Paste the exported ticket content into the ITSM Import tab of the onboarding rough tracker.
  3. Open the Identity Management Portal and navigate to the New Hire Password tab. Set the date picker to start date + 1 day, then paste the user list into the Identity Sheet in the rough tracker.
  4. Copy the contents of the Print New sheet and paste as Values Only into the actual tracker to preserve formatting.
  5. Return to the ITSM report and append – added to tracker to each processed ticket's short description. This prevents the ticket from reappearing on subsequent exports.

Note: The report filter relies on the absence of the suffix above. Always update ticket descriptions before closing the ITSM tab.

Step 2 — AD Pool Provisioning

  1. For each user, look up the corresponding AD security group using the Group Lookup Tool. If the group is not found (this occurs when the value is a pool name rather than a group name), search the correct pool in the Omnissa Horizon Admin Console by region.
  2. Use the provisioning script template (see AD Group Bulk Provisioning above) to populate the user and group arrays. Verify order carefully — User 1 must map to Group 1.
  3. Paste the completed script into Active Directory Module for Windows PowerShell and execute. Review the per-line output before proceeding; any red failure lines must be resolved before Step 3.

Troubleshooting: "Object not found" on a user — verify spelling against the Identity Portal. "Group not found" — re-confirm the pool in Horizon Admin Console and check the region.

Step 3 — Onboarding Portal Upload

  1. Rehires first — check the Identity Management Portal for returning employees and process them before new hires.
  2. Only upload users who have been successfully added to an AD group. If a pool name is missing from the tracker, confirm with the user's manager or account team before uploading.
  3. Copy columns H through K from the tracker and paste into sample.csv, keeping headers intact.
  4. Upload the CSV to the Onboarding Portal with the VDI Hire checkbox selected.
  5. Verify that the Collected LDAP status is green for every user before closing the portal.
  6. Enter the upload date in the Upload Date column of the tracker to mark the batch as complete.

Verification Checklist

  • All ITSM tickets appended with – added to tracker
  • Tracker fully populated — no blank pool names
  • PowerShell output shows no failures
  • Onboarding Portal shows green LDAP status for all users
  • Tracker upload date column updated for the batch
